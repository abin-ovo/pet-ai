## 0.1.2 额度诊断修复（2026-10-20）

- 用户反馈“请求频繁”。使用本机已保存连接，通过 Electron 系统网络向原配置服务发送一条最短测试消息；仅读取并输出脱敏后的状态和错误类别，没有输出密钥或发送聊天历史、回忆。
- 真实响应为 HTTP 429、`error.code=credit_balance_exhausted`、`error.type=insufficient_quota`。根因是 API 预付余额耗尽；上一版按 HTTP 状态把全部 429 误报为请求频繁。参考 [OpenAI 官方错误说明](https://developers.openai.com/api/docs/guides/error-codes)。未收到真实模型回复，不能宣称真实聊天恢复。
- 现按结构化错误类型区分余额耗尽、额度不足、项目/组织费用限制、组织用量限制和临时限流。未知 429 保留状态及检查建议，不猜测一定是限流。只显示本地固定提示，不显示可能包含密钥或私密内容的服务端原始错误。无自动重试。
- 设置新增“检测连接”：使用主进程内保存的连接和加密密钥，只发送固定测试消息；不写入对话、不发送聊天和回忆、不改变宠物关系。检测与聊天互斥，配置更改和退出会取消检测。未保存的配置不能检测。
- `npm test`：47 项通过；类型检查和构建通过。新增回归先确认旧版把额度错误当作限流，再修复并验证。
- `npm run test:e2e`：7 条真实 Electron 流程通过，包括余额不足在设置与聊天的正确提示、失败保留草稿、检测不改变聊天/回忆/关系、服务恢复后的检测成功。测试响应来自 Chromium HTTPS 测试处理器，不能代替真实模型回复。
- 已查看新增设置面板截图，检测按钮、额度说明和结果提示布局正常。
- Mac arm64 0.1.2 应用重新打包成功，包内主进程包含新的额度分类和连接检测。Windows 应用目录构建成功；NSIS 安装器失败，原因是缓存中的 macOS makensis 为 x86_64，当前机器运行 Intel 程序报 `Bad CPU type`（spawn -86）。改为成功生成 Windows x64 免安装 ZIP，解压后运行小团.exe。Windows 本机运行仍未验收，Mac 仍未签名。
- 真实聊天仍受账户余额阻塞，需用户在服务商控制台补足 API 余额或改配可用服务；未执行充值或账户修改。

## 0.1.1 网络修复（2026-10-19）

- 复现用户的连接错误：同一台 Mac 的系统代理路由为本机代理。无密钥 GET 请求到 OpenAI 时，Node 全局 fetch 约 10.6 秒后报 `UND_ERR_CONNECT_TIMEOUT`，Electron `net.fetch` 约 1.2 秒收到预期的 HTTP 401。401 仅证明请求到达服务端，不代表凭据或模型回复成功。
- 聊天默认请求从 Node fetch 改为 Electron `net.fetch`，遵循系统代理。现有服务地址、模型、加密密钥和聊天存档保持兼容。
- 新增单元回归，先复现默认请求错误，再确认 Node 网络不可达时会使用 Chromium 网络并正确发送模型、消息和授权头。36 项单元/组件测试及类型检查通过。
- 五条真实 Electron 流程通过。新增的聊天场景使用 Chromium 专属 HTTPS 测试处理器，验证设置连接、发送、接收回复、清空草稿及磁盘保存的完整链路；测试不向真实服务发送密钥或消息。
- Mac arm64 应用与 Windows x64 安装包均重新构建成功；检查两平台打包后的 app.asar，均包含 0.1.1 版本及 Electron 网络调用。Mac 仍未签名，Windows 尚未运行验证。
- 真实 API 密钥有效性及真实模型回复仍未验证。下方 0.1.0 的 Windows 原生交互、签名等限制继续适用。
