# AI 桌面宠物：第一版产品设计草案

日期：2026-10-18

阶段：用户于 2026-10-18 确认本方案及默认项；尚未进入开发。

平台：macOS、Windows。

## 1. 已确认的方向

一个生活在电脑桌面上的 AI 虚拟宠物，同时带来陪伴感、养成感和轻松治愈。

平时像小动物，通过动作、表情和叫声交流；用户主动找它时，才展开文字聊天。陪伴是日常使用的核心，养成提供长期变化，可爱互动提供即时反馈。

第一版只有一只宠物、一个生活空间、每天几分钟的照顾和交流。后续再扩展换装、探索和宠物社交。

## 2. 本文采用的默认假设

以下默认值已随本方案确认，后续可以通过设计变更调整：

- 优先服务工作、学习时希望获得轻度陪伴的个人用户。
- 外形暂定原创 2D 小猫，圆润、动作清晰；形象可替换，不把物种写死进养成逻辑。
- 首版中文界面、文字聊天；声音默认关闭，可单独开启少量动物音效。
- 一台设备保存一只宠物，不要求注册，不提供跨设备同步。
- 第一版交付用于个人试用和小范围验证；商业发行、订阅及模型费用结算属于后续设计。

## 3. 产品形态与取舍

| 方向 | 主要体验 | 第一版的取舍 |
| --- | --- | --- |
| 桌面常驻宠物＋按需展开面板 | 做事时能看到宠物，想互动时随手打开 | 推荐作为核心形态，需要认真处理焦点、点击穿透和资源占用 |
| 独立养宠窗口 | 进入一个完整的小房间照顾宠物 | 适合更丰富的布置玩法，持续桌面陪伴较弱，后续再扩展 |
| 聊天窗口＋宠物头像 | 以对话推动关系 | 容易验证聊天，但动作和陪伴体验不足，不作为第一版主形态 |

生活空间在首版中指桌面上的一个小窝和一件固定玩具，不建设可布置的完整房间。宠物可以在附近小范围活动，也可以固定在用户指定的位置。

## 4. 第一次使用

1. 启动后出现一只小猫，进行短暂的醒来、观察和靠近动画。
2. 用户给它起名字，也可以采用默认昵称“小团”。
3. 通过一次抚摸和一次喂食认识基本操作。
4. 用户将宠物拖到合适的位置，选择安静陪伴或普通陪伴。
5. 结束引导，宠物进入自己的日常活动；AI 连接设置可稍后完成。

引导不要求填写个人档案。未经用户提供，宠物不知道用户职业、日程或正在做什么。

## 5. 日常交互

| 用户操作 | 宠物反馈 | 规则 |
| --- | --- | --- |
| 单击宠物 | 看向用户，显示轻量操作条 | 不直接弹出大聊天窗口 |
| 选择摸摸 | 眯眼、蹭蹭、尾巴摆动 | 立即响应，不请求模型 |
| 选择喂食 | 走向食物、吃东西、满足地坐下 | 无付费道具，每次有短暂动画和重复反馈限制 |
| 选择玩耍 | 与固定玩具互动 | 一次短互动，不要求完成每日任务 |
| 选择聊聊 | 展开附近的聊天面板 | 只有这时激活输入框；每条发送触发一次模型请求 |
| 拖动宠物 | 被提起，放下后落地 | 区分点击与拖动，不把拖动误判为聊天 |
| 开启安静模式 | 趴下或慢动作休息 | 停止自主移动、声音及主动气泡，仍可手动互动 |
| 暂时隐藏 | 从桌面消失 | 通过托盘或菜单栏恢复，不丢失存档 |

非安静模式下，宠物可自主打盹、伸懒腰、洗脸、看玩具或短距离散步。首版不主动发文字消息，不弹系统通知，不自动抢占输入焦点。

## 6. 养成与关系

采用少量可解释的状态：精力、满足感、亲近程度，以及偏好记录。

- 精力影响活跃和休息动作；满足感影响当下表情；两者都不会降至导致生病、死亡或功能锁定的状态。
- 亲近程度来自跨天的照顾和交流，同一天重复点击不无限增长。
- 离线期间亲近程度不下降。再次启动时，根据离开时长选择欢迎动作，不追算惩罚。
- 用户偏爱的互动会逐渐形成小习惯，例如更常抱着玩具、被摸后蹭近一点。
- 首版使用三段关系变化：初见、熟悉、亲近；阶段带来可见的动作变化，聊天仍然保持宠物口吻。
- 界面以“今天更愿意靠近你了”等描述呈现变化，不用饥饿警报或连续签到施压。

数值和动作选择由本地规则控制。模型只提供对话及受约束的表情建议，不能任意修改存档或宣布解锁未实现的能力。

## 7. AI 对话与记忆

### 表达方式

默认温和、好奇、略带小动物视角。回复以一至三句短句为主，能听用户说话，也能分享与自身生活空间有关的小反应。

例如用户说“今天好累”，它可以回应：“那先靠一会儿吧。我把小窝旁边的位置留给你。”同时播放靠近或趴下动作。它不会声称自己看到了用户的工作、屏幕或真实生活。

### 记忆边界

- 最近对话提供上下文；长期记忆只保存用户明确提供或主动确认的信息。
- 首版长期记忆包括用户希望被如何称呼、明确偏好和用户选择记住的共同经历。
- 面板提供“记住这件事”，宠物可提出记忆建议，但未经确认不自动保存长期事实。
- 用户可查看、修改、逐条删除记忆，也可清空对话。
- 关系阶段和互动偏好属于本地养成数据，不由模型根据聊天内容猜测。
- 模型请求只携带当前对话所需的近期消息、已确认记忆及宠物状态；不读取屏幕、文件、剪贴板或麦克风。

### 连接及失败处理

内部试用默认支持一个可配置的 HTTPS 模型服务端点、模型名称和访问密钥，由试用者自行配置。该设置集中在连接设置页，不放进日常照顾操作条。公共发行需要另行设计服务端代理和费用控制，不在客户端内置共享密钥。

未连接时明确显示“聊天尚未连接”，照顾和陪伴照常可用。请求超时、断网或限流时保留用户输入，允许手动重试；不把固定示例回复当作真实 AI 成功结果。

单次只允许一个生成请求，支持取消；失败不改变亲近程度。退出应用不自动发送未发送的内容。

## 8. 桌面行为与界面

界面由宠物、小型操作条，以及按需打开的面板组成。面板包含聊天、宠物近况、记忆和设置，避免多个独立窗口长期占据桌面。

- 宠物默认位于主显示器工作区右下角，避开 Dock 或任务栏。
- 保存用户最后放置的位置；显示器断开、缩放改变或位置越界时，移回可见工作区。
- 小范围自主活动不跨显示器；用户可手动拖到另一块屏幕。
- 默认在普通应用窗口上方显示；用户可以关闭置顶。首版不承诺覆盖全屏独占应用或所有 macOS 空间。
- 透明背景不能形成大面积不可见的点击阻挡区；宠物和操作控件保留可点击区域。
- 点击其他应用后，关闭临时操作条；已经打开的聊天面板可由用户关闭或按 Escape 收起。
- 菜单栏或托盘提供显示、隐藏、安静模式、设置及退出。
- 开机启动默认关闭，由用户主动开启。
- 提供减少动态效果选项；键盘可访问面板中的操作，聊天面板有明确的关闭入口。

## 9. 技术结构（Electron 已确认）

用户已确认采用 Electron＋TypeScript；互动面板使用 React；宠物动画资产与业务逻辑分离。该选择是基于首版需要同时覆盖两个桌面平台并快速迭代交互的工程判断，不代表已经完成双平台性能或原生验收。

职责划分：

1. 桌面宿主：窗口、托盘、显示器位置、焦点和生命周期。
2. 宠物引擎：本地状态机、照顾规则、关系阶段与动作选择，不依赖网络。
3. 展示层：宠物动画、操作条和面板，消费同一份宠物状态。
4. 对话服务：模型请求、取消、超时与回复校验；表情仅接受有限的动作名称。
5. 本地存储：带版本号的存档、对话和记忆，采用原子写入和最近一次有效备份。

第一版不建立账号后端。访问密钥交由系统支持的凭据保护机制保存，不进入聊天记录、普通存档或日志。展示层使用上下文隔离和沙盒，只通过受限接口调用必要能力。

Electron 提供透明窗口及忽略鼠标事件的接口，但透明本身不会自动实现点击穿透；透明窗口还有调整尺寸等限制。实现时使用固定尺寸宠物窗口和独立面板，并对可点击区域及拖动分别验证。

参考依据：

- [Electron：窗口样式与透明窗口限制](https://www.electronjs.org/docs/latest/tutorial/custom-window-styles)
- [Electron：拖动区域与点击穿透](https://www.electronjs.org/docs/latest/tutorial/custom-window-interactions)
- [Electron：安全建议](https://www.electronjs.org/docs/latest/tutorial/security/)
- [Electron：凭据保护能力及平台语义](https://www.electronjs.org/docs/latest/api/safe-storage)

## 10. 第一版完成标准

以下是未来开发的验收条件，尚未执行或通过：

1. macOS 和 Windows 上分别验证启动、宠物显示、拖动、点击穿透、面板展开、隐藏与退出；只在单个平台运行不算双平台完成。
2. 普通应用输入期间，宠物自主动作不会抢走焦点；安静模式不出现自主移动、声音或主动气泡。
3. 抚摸、喂食和玩耍均有不同反馈；断网也可完成，结束后回到合理状态。
4. 对话可连接真实模型；断网、超时、取消和重试不会丢失输入或产生重复回复。
5. 用户确认的一条记忆在重启后仍可用于对话；删除后不再作为长期记忆携带。删除入口明确提示：原始聊天仍可能出现在近期上下文中，如需同时移除，应一并删除对应对话；已经发送给模型服务的内容无法通过本地删除撤回。
6. 跨天互动能产生至少一种可见的关系变化；系统时间改变及休眠唤醒不会制造惩罚或无限增长。
7. 重启保留昵称、关系、偏好、设置和可见位置；损坏存档可从有效备份恢复，并明确告知恢复情况。
8. 至少检查闲置、动画、聊天和隐藏四种情况下的 CPU、内存与模型调用；闲置不调用模型，隐藏时停止视觉动画。
9. 性能数值在目标设备上实测并记录后再设发布阈值；本设计不预先声称“低占用”。

建议先邀请少量体验者连续试用七天，观察是否自发互动、是否愿意保留在桌面上、能否感知关系变化，以及因遮挡或打扰而隐藏、退出的原因。首轮以访谈和用户自愿反馈收集结果，不默认加入后台行为追踪。

## 11. 后续扩展顺序

1. 更多动作、玩具和关系变化，先改善单只宠物的陪伴质量。
2. 换装、小窝装饰与可控的探索事件。
3. 多宠物形象及独立性格设定。
4. 验证存在真实需求后，再考虑账号同步、订阅及社交。

语音、3D、读取屏幕、自动操作电脑、商城和社交均不纳入第一版。
